# Word widget app design

## Intent
An iPhone app for a Vietnamese speaker learning everyday American English. A home-screen widget
shows a new word with common spoken sentences; tapping plays US pronunciation.

## Goals
- Widget (small, medium, large) showing word, IPA, Vietnamese meaning and example sentences.
- Lock-screen widget (rectangular below the clock, inline above it), new word every hour by default.
- Tap the speaker or a sentence in the widget to hear it without opening the app.
- App with the current word, a searchable word list, favorites and speech-rate setting.
- One notification per day teaching 10 new words with a common sentence each, with action
  buttons that speak the lesson without opening the app.
- Unsigned `.ipa` produced by GitHub Actions for sideloading.

## Non-goals
- Accounts, sync, server, spaced repetition, App Store distribution.

## Approaches considered
1. **Native SwiftUI + WidgetKit, built on GitHub Actions (chosen).** Widgets must be Swift, and
   interactive widgets need iOS 17. No Mac is available locally, so CI builds the IPA.
2. Flutter app with a Swift widget extension. Rejected: two toolchains, widget is still Swift.
3. Web app plus a Scriptable widget. Rejected: no in-widget audio, weaker widget.

## Decisions
- **iOS 17+**, required for `Button(intent:)` in widgets.
- **Audio from the widget** uses an `AudioPlaybackIntent` (`SpeakIntent`) compiled into both
  targets, so iOS runs it in the app process; the app declares the `audio` background mode.
- **Audio session is non-mixable** (`.playback`, no `.duckOthers`): widget taps start audio from
  the background, where a mixable session can be refused. Tapping the widget background opens
  the app and speaks the word as a fallback. Settings shows the build number and the result of
  the last widget-triggered speak, since there is no device log access during development.
- **Daily lesson of 10 words.** `WordSchedule.words(forDay:)` takes ten consecutive positions
  of the scattered word order per day, so nothing repeats until the list is exhausted. The app's
  first tab lists the day's ten words; the widget cycles through them, one per hour.
- **One local notification per day** (`App/NotificationManager.swift`, default 8:00, no server)
  listing the ten words with meaning and one common sentence. The app schedules 30 days ahead
  (iOS caps pending local notifications at 64) and tops up on every foreground and via a
  `BGAppRefreshTask`.
- **Notification actions** ("hear the 10 words", "hear words and sentences") are background
  actions; the delegate awaits the speech so the app stays alive until it finishes. Tapping the
  notification opens that day's lesson.
- **Speech** uses `AVSpeechSynthesizer` with the `en-US` system voice: offline, no API cost.
- **No App Group.** Free-Apple-ID sideloading often breaks App Group entitlements. App and widget
  each bundle `Shared/words.json` and derive the word from the clock (`WordSchedule`), one word per
  hour. The widget passes its word to the app by deep link (`learningwords://word/<index>`).
- **No widget configuration intent.** The widget is a `StaticConfiguration`: the first sideloaded
  build used `AppIntentConfiguration` and stayed on its placeholder on iOS 26, so nothing the
  widget needs to render may depend on intent resolution.
- **App version** is `1.<CI run number>` and the release tag is `v` plus that version, so the
  installed app and its release always match.
- **Build number** is the CI run number, so a reinstall never reuses a cached widget extension.
- **Project file** is generated by XcodeGen from `project.yml`; the `.xcodeproj` is not committed.
- **CI** builds with code signing disabled, zips `Payload/` into an IPA, uploads it as an
  artifact and attaches it to a GitHub release.

## Known limits
- Not run on a device or simulator during development (Linux host); CI only proves it compiles.
- Speech rate set in the app reaches widget taps only because the intent runs in the app process.
